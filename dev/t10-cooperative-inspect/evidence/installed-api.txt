Inventory selection shape
-------------------------
ISInventoryPaneContextMenu.createMenu(player, isInPlayerInventory, items, x, y, origin)
accepts raw InventoryItem values or grouped tables with an .items array.
ISInventoryPane.getActualItems starts grouped iteration at index 2 because
.items[1] is the dummy display duplicate, and it deduplicates by item identity.

Inventory event order and signature
-----------------------------------
After vanilla menu construction, the installed file calls:
  triggerEvent("OnFillInventoryObjectContextMenu", player, context, items)
The adjacent vanilla comment explicitly describes adding items without mod
conflicts. The event therefore receives the original selection shape, not the
normalized result returned by ISInventoryPane.getActualItems.

World event order and signature
-------------------------------
After vanilla world-menu construction, the installed file calls:
  triggerEvent("OnFillWorldObjectContextMenu", player, context, worldobjects, test)
Dropped inventory subjects are IsoWorldInventoryObject values and resolve via
getItem(). During controller preflight, an additive callback must call
ISWorldObjectContextMenu.setTest() only when it would add a command.

Cooperative menu/event surfaces
-------------------------------
ISContextMenu exposes addOption, addOptionOnTop, getOptionFromName and
removeOptionByName. Event collections support Add and Remove; installed vanilla
code uses Remove in ordinary callback lifecycle management.
