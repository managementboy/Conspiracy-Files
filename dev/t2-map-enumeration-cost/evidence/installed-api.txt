Installed Kahlua memory-counter semantics:

`se.krka.kahlua.stdlib.BaseLib.collectgarbage(..., "count")` calls
`Runtime.freeMemory()` and `Runtime.totalMemory()`, subtracts free from total,
divides by 1024, and returns used JVM heap KiB. `collectgarbage("collect")`
calls `System.gc()`. Therefore T2's heap deltas are observed retained JVM
used-heap changes while the Lua index is held; they are not exact Lua-object
sizes and are not total process working set.

Official Build 42 Javadocs independently list the same path and record getters:
