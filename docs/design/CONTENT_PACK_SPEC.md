# Content Pack Specification

**Status: Deferred post-v1.**

The original planning assumed an external data-driven content-pack system. Engineering review supersedes that delivery assumption:

- v0.1 and v1 use one built-in authored content set;
- no generic external pack schema is finalised yet;
- the first real thread (`test/fixtures/THREAD-001-DEAD-AIR.md`) is used to pressure-test the domain model;
- a generic pack schema is extracted only after at least a second real content set exists;
- future pack compatibility must separate content revision from Conspiracy-Files schema/API compatibility and PZ minor-line compatibility;
- ordinary typo/text-only compatible revisions must not require save migration.

Long-term external-pack capabilities from the discovery baseline remain ideas, not v1 requirements.
