# AI Content and Provenance Policy

## Development-time AI
AI may write letters, diary entries, descriptions and template variants. No separate human approval is required before text ships; the owner reviews it in play and asks for changes (P4-R97, 2026-09-14). Shipped text is treated as authored game content in-fiction.

The project should disclose in repository/Workshop documentation that AI-assisted text may be used, without adding immersion-breaking labels to every item. Future content-pack manifests should include provenance metadata once packs exist.

## Runtime AI
Optional only. Runtime outputs are interpretations/summaries, never evidence. The data model records provenance. Normal case record styling may remain unified, but an optional provenance toggle can show whether text/linkage came from game/authored fact, player note, system inference or runtime AI.

No provider credentials are stored in saves or committed to the repository.
