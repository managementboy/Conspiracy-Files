# Muldraugh location intake

The owner will supply 12 places they find interesting for conspiracy stories. They may send a numbered list, a table or map links; a special file format is unnecessary.

For each place, collect:

| Owner input | Needed now? |
|---|---|
| Place name or a description identifying it | Yes |
| Coordinates, a map link, or an approximate position/landmark | Helpful; we can resolve it later |
| Interesting features or the reason for choosing it | Helpful story context |

No container indices, exact room boundaries or proof of technical eligibility is requested from the owner. An interesting-place nomination is reusable content input, not a prescribed plot or per-generated-case approval.

After receipt, Codex preserves the supplied description/source, assigns stable location IDs, and enriches map/build applicability, area identity, bounds, candidate storage types and capability evidence from available map research/source data. Unverified facts stay unknown. The engine must later check actual containers automatically.

Maintain separate nomination and technical-validation status. Do not turn an owner nomination into an observed capability. Keep invented test locations in test/fixtures/synthetic_locations.lua; never mix them into the real Muldraugh catalog.

This owner-supplied starting set replaces the initial plan to source every prototype place from T2/T3 alone. Existing research remains useful for enrichment and later supplements. The eventual database can combine both sources.
