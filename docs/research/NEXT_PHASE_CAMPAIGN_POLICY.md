# Campaign scheduling ledger (offline)

`dev/next-phase/CampaignPolicy.lua` is a bounded metadata ledger for later case scheduling. A record stores only stable case ID, creation time, survival hours, creation anchor, approved radius, and the two selected site IDs. It never stores a full case, titles, clues, discoveries, or evidence. Existing generated-case and evidence roots remain external authoritative data.

The caller supplies an explicit configuration: `minGapHours`, `maxConcurrent`, and `maxRetained`. No numeric default is embedded or owner-approved. The caller also supplies the current active-case IDs/count, and every active ID must already be retained. This policy does not invent a lifecycle, parking, completion, or solved-state model. Reaching either cap defers creation. Retention never deletes records or known evidence.

Creation anchors and radii are copied into immutable ledger records; player movement cannot rewrite an older case's reach. Survival and creation hours may be fractional, while record chronology remains ordered. Radius is derived from `Reach.radius(survivalHours)` and a mismatch rejects. Candidate sites cannot repeat any retained site's ID, and scarcity defers rather than widening reach. `stage` requires an explicit peer-root table (use `{}` only for isolated offline work), reserves its own ledger key, and validates supplied real case/marker/address roots through the existing combined validator before returning a replacement candidate for an external writer. A future adapter must supply all actual peer roots. This is not a live schema, migration, or writer.
