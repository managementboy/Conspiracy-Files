# Precommit location-readiness contract (offline)

`dev/next-phase/LocationReadiness.lua` reduces bounded observations for exactly two fixed candidate sites before a generated case is committed. Metadata may describe storage as observed, unknown, or absent, but can never verify a live container. A `loaded` observation creates a strictly newer load epoch; only a positive container verification for that current epoch makes a site ready. A negative current verification makes it unsuitable. Unloading clears verification and leaves the site waiting; a stale verification cannot revive it after reload.

Commit authorization is advisory precommit state: the actual adapter must revalidate both targets immediately before its authoritative commit. A positive event represents an actual container verification at that moment, never a guarantee against later container mutation. The reducer freezes after commit. It does not reroll or relocate sites, create/respawn items, infer loss from absence, persist schema, or implement Session's postcommit recovery rules. Invalid observations are rejected before state replacement. This is an adapter contract for a later precommit integration only.
