## Why Fieldnote, and what it buys

- **The screen is 320 × 422 at (40, 50).** That is the doubled Palm canvas the
  typeface was cut for. Measured on this font: the current 225-wide glass puts
  **52 characters** on a line; a real Palm put 37; Fieldnote at 2× type puts
  **36**. The type is not too small — the lines have been 40% too long. Owner
  chose to keep 23 rows once (P4-R82); the argument was never put to him as
  52-vs-36 characters. Put it that way.
- **A real rocker.** Today UP and DOWN share the four keys. Fieldnote has four
  keys *and* an up/down rocker: `MENU / UP / DOWN / BACK` no longer fight for
  slots.
- **Geometry is generated, never transcribed.** `build_fieldnote.py` reads the
  design's `manifest.json` and emits `Geometry.lua`. Re-running it is the only
  way the device changes, so the Lua cannot drift from the design.
- **No art pipeline.** The SVG → four PNG exports → `build_organiser_case.py`
  → hit-box detection chain, which cost a whole day of blurry upscales,
  misaligned buttons and a power tab drawn off the edge of the picture, goes
  away entirely.

## The replacement, as work packages

Do them in order. Each has a gate. Do not skip a gate to save time — the
silent-failure class here (a wrong hit box does nothing; a wrong category
shows the wrong word) is exactly what the gates exist to catch.

**WP1 — Mount Knox.OS on the Fieldnote LCD.** In `OrganiserScreen.lua`,
replace `Generated/OrganiserCase.lua`'s `glass` with
`Fieldnote.Panel.metrics().lcd` and draw the case via `Fieldnote.Panel`'s
`prerender`. Knox.OS's own drawing needs no change beyond its origin: it
already draws into a `K.begin(...)` context whose size is the glass. Type
goes to **2×** — use the existing `2x` glyph set, not a scale factor on the
device. Gate: `tools/autotest/checks/hardware.sh` PASS (it opens every

below. Gate: `hardware.sh` wake/press/lamp sections PASS; the Fieldnote
`boot_test.sh` still PASS (its probe drives the same panel).

**WP3 — The lamp and the power model.** Fieldnote's design has **no power

**WP4 — Retire the bitmap case.** Delete, and remove every reference to:

## Decisions the owner must make (findings attached)

1. **The two freed keys.** With the rocker taking UP/DOWN, keys 2 and 3 are
   free. The design names them `TASK` and `ADDR` (and `NOTE`, `FIND` for 1
   and 4). Options: direct program keys again (the Palm way), or leave them
   unmapped until a use earns them. The silkscreen labels are *in the design*
   now (NOTE/TASK/ADDR/FIND), so whatever they do should match the words.
2. **Label size on 4K — unresolved, evidence pending.** On the owner's
   3200×1894 machine the four key labels draw **on top of their icons**; on
   the Linux dev machine the same code measures them 3–4px clear. The only
   machine-dependent input is the font metrics; a UI font-size setting is the
   leading hypothesis but is **not proven** — an attempt to prove it locally
   was inconclusive (the option setter did not take mid-session). A metrics
   script is staged in the eval inbox and runs the moment the owner restarts
   his stream with `stream_log.ps1 -Eval`; it prints his real `Small`/`Medium`
   ink metrics. **Do not guess at this. Read his numbers.** The robust fix
   regardless: size each label to the room the manifest gives it
   (`baseline − icon_bottom`, 11–12px) and fall back (smaller font, or icon
   only) when the ink will not fit.
3. **Wear scuffs** (C19) default on per the manifest. Keep, or pristine?
4. **The 320-wide glass** was declined once as P4-R82 on a 23-vs-16-rows
   framing. Fieldnote makes it free. Re-raise it as 52-vs-36 characters.

## How to work this project — the parts that cost hours to learn

- **Every engine call against the jar, never from memory.** `drawRect` takes
  alpha **first**; `drawText` takes it **last**. `MeasureStringY` is the full
  box; `getFontHeight` is the line height; the baseline of a caps label is
  `MeasureStringYOffset + MeasureStringYReal` (read out of
  `AngelCodeFont.getHeight` bytecode). All three wrong guesses put text on top
  of icons.
- **Kahlua single-file mode executes;** `run.sh --parse <files>` compiles. A
  client file that requires `ISPanel` fails the first "whether or not it is
  valid".
- **The eval channel reaches the owner's game.** `tools/cf_eval.sh` writes
  `dev/eval/inbox/cf_inbox.lua`; `stream_log.ps1 -Eval` fetches it from the
  **main checkout**, not a worktree — set `CF_EVAL_DIR=/home/elkin/Conspiracy-Files/dev/eval`.
  The other session's `pz.sh eval` writes the same file and will clobber a
  staged command.
- **The play log is a query, not a paste.** `tools/log.sh`; owner notes are
  `mod=owner`. The stream copies the whole file each send, so an unchanged
  file just means nobody played.
- **Every check claims the machine** (`claim_game`). `Xvfb` used to inherit
  the lock's descriptor and hold it forever — fixed with `9>&-`.
- **Rules that do not move:** never handle Steam passwords or Guard codes;
  never delete, reset or rewrite the owner's save — a rules change needs a
  fresh game, say so; publishing to the unlisted item is pre-authorised after
  a passing boot check, run `tools/publish_workshop.sh` without asking; say
  **WINDOWS play machine** or **LINUX dev machine** before every command;
  commit without asking, owner decisions into `DECISIONS.md`; the mod never
  states what the player has not earned — a name on a document is a lead.
