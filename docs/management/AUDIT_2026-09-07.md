# Audit — 2026-09-07, after 54 commits in one session

Checked rather than assumed. Each finding lists how it was verified.

  produced no change, so the copies embedded in `Notebook.lua` match their
  sources.
- **Canonical save budget accounts for every root that is written.** Two tags

## Findings, most serious first

### 1. Seven modules load only by PZ executing them automatically

Nothing `require`s these, and nothing reads them off the shared table:

    AutomaticInvestigations   DebugHarness   IdentityProbe   LocalPersonHooks
    SessionGuide              Generated/PlaceNames           init

Two are load-bearing. `AutomaticInvestigations` is what makes cases appear
without console commands - the owner's standing requirement. `LocalPersonHooks`
installs the door and transfer hooks, so the entire person/key strand depends on
it. Both self-register at file scope and are reached no other way.

They demonstrably work today. The concern is that **`PlayerVoice` did exactly
the same thing and did not load** until an explicit `require` was added
(86ade2c). I cannot currently explain the difference, which is itself the
problem: we are relying on a load mechanism whose behaviour we have not
established.

**Recommendation:** add an explicit `require` for the two load-bearing modules
from something already proven to load. Cheap, and it converts an unexplained
risk into a certainty. Do not do this blind - first establish why PlayerVoice
behaved differently, or the same surprise will recur elsewhere.

### 2. The observed-key catalogue path is effectively dead code

`ObservedKeyAdapter` matches a key id only against the current case's own
locations, because that is all persisted state holds. A random corpse's house
key will essentially never match one of those, so the path ships, costs engine
calls, and can almost never fire. This is recorded in the commit that added it
(ff9598d) and superseded by the door-observation path (8f70014), which needs no
lookup at all.

**Recommendation:** decide whether to delete it or extend it once the T3
catalogue is persisted. Leaving unreachable code in place invites someone to
"fix" the wrong half later.

### 3. Test doubles mostly cannot catch the call-form bug class

Only five test files demand a receiver on their engine doubles:
`domain_core_spec`, `observed_key_adapter`, `observed_key_door`, `player_voice`,
`reachability_gate`. Every other test that mocks engine objects uses a
permissive plain table, which accepts both `obj:method()` and `obj.method()`.

That is precisely how a module whose every engine call was malformed passed the
suite and threw on the first real object (77d46ef), and how two silent no-ops
shipped (d747a25, 5f12fa1).

**Recommendation:** make the receiver-demanding double the default for any test
that mocks an engine object. `test/reachability_gate.lua` has the pattern.

### 4. The identity render hook got more expensive, unmeasured

`afterRender` now resolves each row's own container - `getContainer`,
`getParent`, `getContainingItem`, and sometimes `getDisplayName` - where it
previously made one call per row. Up to sixteen rows per pane per frame, on
every non-player inventory pane.

This was the right fix (it is what made the merged proximity view work), but the
cost has never been measured against the <=2 ms/frame budget.

**Recommendation:** measure before release. A per-pane cache keyed on the
container would likely remove most of it.

### 5. Diagnostics are shipped, not gated

The build logs extensively under `[CF-*]` tags. That was decisively useful today
- it is how `proxInv` was found - and the volume is bounded. But it is
development instrumentation in a shipped artifact and should be behind a debug
switch before any release build.

### 6. Reverted work is parked and must not be forgotten

The role/carrier schema (6ef0324) was reverted (d97f6cc) because regenerating a
case invalidates every saved case, which killed the retained fixture mid-test.
The four card and ticket carriers are therefore unreachable again. Re-land it
together with a generator revision bump when the fixture has served its purpose.
