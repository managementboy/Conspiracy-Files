## What was built today (this session)

- **Knox.OS**, a fake operating system on the device: a widget kit following
  Palm's own shapes, an Applications launcher with an icon grid, clock and
  battery, and seven programs — FILES, NAMES, PLACES, DATES, TO DO, NOTES,
  HELP, plus a debug-only SITES that shows where the clues are.
- **The device**: a real item, battery-powered (declared as a radio, which is
  why it must stay one — see KNOX_OS.md), losable, spawning rarely in offices
  and electronics shops, with the owner's own case art and a Palm OS typeface
  under CC BY-SA.
- **The hand rule**: equip to open, unequip to close, including the boot
  screen. Inspecting a document records it and opens nothing.
- **Continuity after death**: the record lives in the world, so any organiser
  reads it — your own, off your own corpse, or one from a drawer.
- **The old notebook window is retired**: not a fallback any more, debug only,
  and every view it had now has a home in Knox.OS.
- **Five retry loops removed.** Four were costing the player's machine work
  continuously in normal play: derived clue facts rebuilt twice a second, three
  separate address lookups repeated per refresh or per scheduler step, and
  placement retrying a refused save ten times a second.

## The tests

`tools/autotest/suite.sh` runs nine checks, each booting a real game
(~40 minutes). All nine have passed on this build; the last full run was 8/9
with the death check failing, and that failure is fixed and verified alone.

Two habits worth keeping:

1. **Every check claims the machine** (`claim_game`) and waits its turn. Two
   sessions and one game machine caused four false failures before this
   existed.
2. **When a check says something retries forever, trap the function and read
   the stack trace** rather than reading code. It found in ten minutes what an
   hour of reading did not — three times.

## Rules that are not negotiable

- Never handle Steam passwords or Steam Guard codes.
- Never delete, reset or rewrite the owner's save. A rules change needs a fresh
  game; say so, do not do it for him.
- Publishing to the unlisted Workshop item is pre-authorised; run
  `tools/publish_workshop.sh` after a passing boot check, without asking.
- Always say which machine a command runs on: **WINDOWS play machine** or
  **LINUX dev machine**, and which shell.
- Verify an engine call against the installed jar, never from memory
  (`tools/verify_api.sh`). This was broken twice today and cost an hour each
  time.
- The mod never states what the player has not earned. A name on a document is
  a lead, not an identity. A smarter screen does not change that.
