## Defect 1 — the outfit lead never reaches the notebook

Phase 1's headline is that a body's outfit and a document found on it are two
separate observations the notebook refuses to reconcile. `IdentityObservations`
has the text for it. **It fired in neither natural scenario.**

`IdentityObserver` captures the body token once, at record creation:

    token = source=="corpse" and corpseToken(corpse) or nil

Two independent routes make that nil.

**1a. Ordering race.** `corpseToken` reads `cfObservedSource`, which
`LocalPersonIntegration` only stamps when an item is moved off the body. Read
the ID before looting - the natural order - and the record is written first:

    f:20410  [CF-LEDGER] #2 identity ...243638380
    f:20429  [CF-OUTFIT] recorded outfit for token corpse-item:1792113713

Nineteen frames too late, and nothing recovers: `seen[key]` stops the item ever
being re-observed, and the model only appends records, never updates one. The
source comment claiming "an unstamped body just means the outfit line waits for
a later render" is wrong - there is no later render.

**1b. Classification.** An ID inside a wallet is classified `container`, so the
token is nil regardless of ordering. Jarvis Harding's outfit was recorded
12,000 frames *before* his ID was read and still produced no outfit line. The
notebook says "inside Wallet" where Reyes Varela says "among a corpse's
belongings".

This one is not a judgement call: `[CF-PERSONNAME] recorded name for token
corpse-item:1067933060` proves the mod knew which body the wallet came from.
The wallet carries the stamp from being moved off the corpse.
`IdentityObservations` classifies by immediate container and discards it.

**Fix direction:** inherit the token from a containing item that carries
`cfObservedSource`, and backfill a nil token rather than capturing it once.

## Defect 3 — the silent returns make defect 2 undiagnosable

`AUDIT_2026-09-07.md` says the wallet defect is "narrowed to nested container
panes with a diagnostic ready to name the failing check". That is not true.
`gate()` covers the first three checks in `afterRender`; the ten below it return
silently. During the session the observer skipped the wallet pane with **no log
line at all**, because it passed every check that logs and failed one that does
not.

This is lesson 1 exactly, in the module whose own header cites it. Throttled
logging on those returns would have named the check in one session instead of
leaving the defect narrowed-but-unfixed across two.
