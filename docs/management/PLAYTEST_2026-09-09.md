Builds `DEV-0.8.19` through `DEV-0.8.25`, played on the Windows machine and
streamed live. S1 of `TESTING_PLAN_TO_V1.md` is complete.

## O3 closed — observedKeyDoor works

The last major feature never seen working, verified end to end:

    [CF-PERSON] observedKeyDoor building=11259175162085419 keyId=98122214
                source=corpse-item:585873113
    [CF-LEDGER] #2 connection observedKeyLead:door:corpse-item:585873113
    [CF-VOICE]  "This key came off a body, and it opens this door."

The Set B named voice line fired with halo and sound. Every element came from
the game: it placed the corpse, dressed it `Farmer`, put a residence key in its
pocket, decided which door that key opens, and named the building 305 Perrine
St. The mod noticed and connected, and the entry refuses to conclude who the
body was, that they lived there, or that they owned it.

This is the design's central claim - the game supplies facts, the mod supplies
structure - demonstrated for the first time.

## O4 closed, and it was never what we thought

Three sessions had the "wallet defect" narrowed to nested container panes. It
had nothing to do with nesting.

`ISInventoryPane.dragStarted` does not mean a drag is happening. Vanilla sets
it when the mouse moves four pixels while a button is held, and clears it in
exactly one place, `onMouseDown`. It is never initialised. So an ordinary
imprecise click set it, and the observer - testing it alone - abandoned that
pane permanently. Selecting a row appeared to "fix" it only because selecting
is a mouse-down.

The remaining half was not a defect at all: a wallet inside a corpse is not a
container the pane can show, so there was never a wallet pane to observe.

Found in about ninety seconds once the silent return could speak.

## Six defects fixed

1. **Stale `dragStarted`** abandoned a pane forever after any click (0.8.20).
2. **`wore a police`** - the outfit sentence carried an article that only works
   for some of 78 labels. `Generic03` had hidden it for two days by suppressing
   the sentence entirely, so it never rendered with a real value (0.8.22).
3. **`Generic_Skirt` leaked** as "generic skirt". The rule stripped trailing
   digits and compared the whole stem, catching `Generic03` and missing this.
   Now judges the leading word, so `Cook_Generic` still survives (0.8.23).
4. **`verboseDoors` crashed Lua.** The module was require-only and never
   assigned itself to the `ConspiracyFiles` table, while its own header
   documented the console line. A diagnostic nobody can turn on is not a
   diagnostic (0.8.24).
5. **Wallet provenance discarded.** The mod stamped the wallet with the body's
   token, bound a case to that corpse, and told the player only "inside
   Wallet" (0.8.21).
6. **A building id in player-facing prose** - "the building at
   11259175162085419". Now "305 Perrine St", with no identifier at all when the
   address book has none (0.8.25).

Four of the six were only findable because the silent returns were
instrumented the day before.

## What the outfit evidence actually says

Corrects the conclusion recorded on 2026-09-08 that distinctive outfits are
rare. Five bodies, five outfits, four meaningful:

    SportsFan, SportsFan, Police, Farmer, Generic_Skirt

Outfits are common and the game names them well. The problem is narrower: the
outfit sentence only renders on an identity record, identity records only exist
where there is a document, and the only body carrying a document was the one in
a generic skirt. A police officer and a farmer both had real outfits and no
paper at all.

**Suggested change, owner's call:** when the generator binds a case person,
prefer a corpse whose outfit is not generic. The outfit is already readable at
bind time. That turns Phase 1's disagreeing-leads from a lottery into something
reliable, without inventing anything - still the game's corpse, still the
game's outfit, only a choice between real bodies.

## S2 — physical identity (E05): passed

Tested on `DEV-0.8.27`. The notebook's account of where a document is was
missing entirely from generated cases until this session; the older authored
path had it and the newer one had quietly never been wired to it.

| State | Result |
|---|---|
| Carried or nearby | "Last accounted for..." |
| Player walks away | "Not seen recently. Its whereabouts are uncertain." |
| Player returns | recovers to accounted for |
| Save and reload | passes; reports "not checked since you loaded" until the first scan |
| Destroyed (trash can) | "whereabouts are uncertain" |
| In a vehicle | not exercised; the scan covers vehicles and the owner accepted it |
| Two copies | not reproducible deliberately |

**The destroyed case is the one worth recording.** The notebook does not say
the document was destroyed, because it cannot know that - the scan sees the
player, two tiles around them, their vehicle and the original container, so a
burned document and one left in another town look identical from here. It says
it cannot find it. That is truthful, and refusing to claim destruction is the
same restraint the rest of the notebook applies to identity.

**E05 is met on the generated path**, which it was not at the start of the day.
