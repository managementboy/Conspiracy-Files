The second case's scan: diagnosed and fixed — 2026-09-21
source 4722a79+ / DEV-0.46.0-writing-rebuild, Linux hidden run (Mesa llvmpipe)

THE FAULT
  A campaign run produced two cases and then stopped, with the generator
  reporting why=busy, preparing=true, nothing overdue, indefinitely. The
  nineteen failures in 20260921T074140-campaign are that one cause.

  The metadata scan for a later case never ran a single step. Measured with a
  read-only counter added to the job (T.progress):

      second scan, before the fix:  phase=scan idx=0/9978 ticks=0 steps=0
                                     - unchanged after ten minutes, no error

  The job existed and the scan was never called. Its OnTick handler had been
  removed from inside OnTick's own dispatch when the FIRST scan completed
  (T.cancel is reached from step(), inside tick(), inside the dispatch), and
  the Events.OnTick.Add in T.start could not re-register it because
  R.nextCase runs inside the scheduler, which itself runs inside an OnTick
  handler. Adding and removing handlers during the event's own dispatch is
  what broke it, in both directions.

THE FIX
  The handler is registered once when the module loads and never removed. It
  already returns immediately when there is no job, so leaving it registered
  costs one nil test per frame. T.cancel now only drops the job. A module
  reload takes the previous closure off the list at load time, which is
  outside any dispatch. The owner-triggered diagnostic in the same file had
  the identical self-removal and now parks itself with a flag and is removed
  on the following frame.

A CORRECTION TO MY OWN EVIDENCE
  I first concluded that Events.OnTick.Add had been corrupted session-wide,
  on the strength of a probe handler added through the eval harness that
  recorded 0 ticks. The control disproves it: on a FRESH world, with the
  scan demonstrably running (ticks=78, idx=1284), the same probe still read
  0. Handlers added through the eval harness never fire. The probe was never
  evidence about anything. Every number above comes from the mod's own
  counter instead.

STILL OPEN
  The scan now finishes, and the second case still does not arrive: 10

  scheduler that a live case's placement, filler, relocation, identity and
  carrier jobs also share - has not been instrumented. That is the next
