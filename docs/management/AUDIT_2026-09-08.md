# Audit — 2026-09-08

Written after the first two-machine playtest, which found three defects by
accident. This looks for the rest deliberately: what the engine actually
offers, what the code assumes, and whether anyone has solved this before.

## 1. Prior art

Searched the Workshop and the wider web for a mod that generates
investigations. **Nothing does what this does.** The niche is unoccupied, which
is worth knowing in both directions - no one to learn from, and no one to be
compared against.

Three neighbours are worth reading, one of them closely:

- **Item Stories [beta]** (Workshop `3037988451`, B42 version `3569303590`) is
  the closest analogue. It spawns items into buildings from a "story" system
  that targets rooms by PZ room definition and furniture by sprite name, drawing
  from room loot tables. Independently arrived at two things we did:
  **it processes one room per tick** rather than scanning at once, which is the
  same conclusion T2 reached from measurement; and it constrains placement by
  **room type**, which is our Phase 2.
- **Immersive Lore** (`3000924731`) is 188 hand-authored stories keyed to spawn
  locations, taking community submissions. It shows the appetite is real, and
  shows the ceiling of authored content: 188 stories is a large volume of
  writing for a fixed, finite experience. Generation is how we beat that, and
  that difference is the product.
- **Zomboid Storylines** (`3620552991`) adds quest chains and randomised events.
  Instructive as a contrast: it sets objectives, which we deliberately never do.

**Assumption this challenges.** Item Stories only generates in rooms **without
existing vanilla randomised house events**, to avoid colliding with them.
Nothing in this repository mentions vanilla house events at all - not the code,
not the design docs, not the research. Either we are placing documents into
rooms the game also decorates, and have not noticed, or the collision does not
matter. We do not know which, and we should. See open question O1.

## 2. Engine API surface

`tools/verify_api.sh` now checks every engine method the mod depends on against
the installed `projectzomboid.jar`, walking superclasses. **All 21 present.**

This exists because lesson 4 in PM_HANDOFF ("verify an API against the installed
game, never from memory") was a good intention with no command behind it. It is
now `tools/verify_api.sh`, and it should run whenever the game updates: a
Build 42 point release that removes or renames a method would otherwise show up
as a feature silently doing nothing, which is the hardest failure this project
has to diagnose.

One trap worth recording: a naive `javap -public` on `IsoDeadBody` reports
`getModData` **missing**, because it is declared three levels up on `IsoObject`.
Checking without walking the hierarchy produces confident false alarms. The
tool walks it.

## 3. Silent returns: the systemic risk

All three defects found on 2026-09-08 were silent early returns or silent
misclassification. None could have been caught by the suite, and none announced
itself. The shipped tree contains **252 silent returns**.

| Module | Silent returns |
|---|---:|
| Notebook.lua | 62 |
| LocalPersonIntegration.lua | 42 |
| ClueMarkers.lua | 20 |
| ContextMenu.lua | 15 |
| IdentityObserver.lua | 8 |

Most are legitimate nil-guards in pure helpers. The dangerous ones are in
**player-facing gates**, where the cost of a wrong guard is a feature that
appears not to exist.

`LocalPersonIntegration.lua` is the sharpest case: 42 silent returns, and it
owns `observedKeyDoor`, which has been on the "not verified in play" list since
it was written. A door that produces nothing has been indistinguishable from a
door nobody tried. That path is now instrumented behind
`ConspiracyFiles.LocalPersonIntegration.verboseDoors`, naming all six ways it
can decline.

**Recommendation.** Do not instrument all 252. Instrument every gate that sits
between a player action and a visible outcome, opt-in and throttled per reason,
as `IdentityObserver` and now the door path are. The pattern costs nothing when
off and turns a multi-session mystery into one line of output.

## 4. What the playtest changed about our assumptions

- **"An unstamped body just means the outfit line waits for a later render."**
  False. `seen[key]` guaranteed there was no later render. Fixed, and the
  comment that asserted it is gone.
- **"The wallet defect has a diagnostic ready to name the failing check"**
  (AUDIT_2026-09-07). False. The diagnostics covered the checks that pass.
- **"An ID inside a wallet is a container observation."** True but useless: the
  wallet carries the body's stamp, so the provenance was available and thrown
  away.
- **A global log throttle is adequate.** False. One shared timer let the
  commonest reason hide every other; 51 routine lines buried the one that
  mattered.

Common shape: each was a correct-looking local decision that lost information
another module already had.

## 5. Open questions

- **O1. Vanilla randomised house events.** Do our placements collide with them?
  Item Stories thought this mattered enough to exclude such rooms. Needs a
  spike: enumerate rooms carrying a vanilla event, compare against placement
  candidates, decide whether to exclude.
- **O2. Distinctive outfits have never been seen in play.** `readable()` is
  unit-tested, but every corpse observed so far wore `Generic03`. Until a body
  in a security guard's uniform appears in a notebook entry, Phase 1's
  disagreeing-leads case is proven only in tests.
- **O3. `observedKeyDoor` remains unverified.** Now diagnosable. Needs a
  **vanilla** house key from a corpse - a case key is explicitly excluded by
  `observedCorpseKey`, which is why testing it with the case key produced
  nothing.
- **O4. Wallet contents needed a click.** Observed 2026-09-08, not reproduced
  since; the corpse pane records without interaction. Possibly specific to the
  wallet pane's geometry at the moment it opens.
- **O5. Steam Workshop delivery is unreliable as a dev loop.** It served stale
  files at least three times in one afternoon, twice reporting no update
  available. The local `scp` install is the loop; the Workshop is for release.

## 6. What is genuinely solid

Worth recording, because an audit that only lists faults distorts the picture:

- The domain core is PZ-free and tested under plain Lua 5.1; 53 suite tests,
  65 standalone, 73 files compiling under the engine's own compiler.
- Performance holds under real load: 9,978 buildings scanned, peak 2 ms, zero
  frames over budget across 583 frames.
- The cautious-wording rule survives contact with real output. The notebook
  says a name on a document is a lead and refuses to identify the body, in the
  exact words the design asked for.
- Provenance separation works with two corpses side by side: three bodies, three
  distinct tokens, no cross-contamination.
- Occupations and outfits come from the game, never invented.
